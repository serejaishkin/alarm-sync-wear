# WakeSync phone UI direction

This is the design contract for the next phone UI pass.

## Keep
- Existing WakeSync visual identity, colors, background and personalization settings.
- Existing Sleep Mode implementation and settings structure; do not replace it with Google Clock's Bedtime implementation.
- Existing advanced alarm features and sync behavior.
- Current section structure unless an existing section already maps naturally to a Google Clock concept.

## Borrow from Google Clock
- Information hierarchy and discoverability of common alarm actions.
- Clear primary alarm list, add-alarm action, and concise per-alarm controls.
- Familiar organization for alarm time, repeat days, label, sound, vibration, snooze and related options.
- Keep advanced WakeSync options behind the existing settings/editor structure rather than removing them.

## Personalization
Personalization remains a first-class setting. It must not be removed or replaced. The design should leave room for future Wear-specific personalization controls.

## Important constraint
This document describes structure and UX direction only. It is not permission to copy Google Clock branding, assets, proprietary strings, or replace WakeSync's existing functionality.
